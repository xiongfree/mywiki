# mywiki

个人 AI-算法 技术笔记的公开版本。三篇长文，讲的是同一件事：Scaling 与 Infra 的相互作用——模型规模能放大到哪，取决于硬件兑现了多少；而硬件的约束又反过来决定架构往哪收敛。LLM 侧是 `llm_arch_evolution.md`；推荐侧两篇，`rec_model_scaling_infra.md` 是通读后的整理，`scaling_infra_papers_breakdown.md` 是它的逐篇论文精读底稿。

| [rec_model_scaling_infra.md](./rec_model_scaling_infra.md) | 推荐大模型 Scaling&Infra（2025 → 2026）：六层演进体系 + 1 条正交诊断线（表征健康）+ 代际拐点 | 约 12 万字 / 4 节 + 附录 | 2025-2026 年工业界 25 篇核心工作 |
| [scaling_infra_papers_breakdown.md](./scaling_infra_papers_breakdown.md) | 上一篇的论文底稿：25 篇逐篇精读 + 八个横向维度 | 约 17 万字 / 25 篇 + 8 维度 | 同上，逐篇拆到机制层 |

三篇的关系：**同一套方法论，在两个行业推导出了不同的解。** 两边的瓶颈不在一个地方——LLM 卡在显存和长上下文，推荐卡在小算子碎片化和 O(B) 候选打分，所以尽管都在做 Scaling，落地手段差别很大。先看 LLM 那篇再看推荐那两篇，比较容易判断哪些经验可以直接借用，哪些照搬会出问题。

推荐的两篇是一组，分工明确：`rec_model_scaling_infra.md` 负责脉络和判断，读起来快；`scaling_infra_papers_breakdown.md` 负责证据，逐篇写清每篇论文的机制、动机和线上数据。**前者的每个结论都能在后者找到对应的论文出处**，想核实某个数字或某个机制的准确表述，查后者。

## 📖 llm_arch_evolution.md —— LLM 模型结构与 Infra 演进深度脉络（2017 → 2026）

> 把 LLM 架构的相关论文一篇篇读下来之后写的总结，带个人观点，不是中立综述。重点不在"有哪些技术"，而在四件事：五条路线各自是谁接了谁、为什么要这么改；每个技术具体是怎么起作用的（给公式，也带具体数字算一遍）；这几条路线之间如何互相影响；以及显存、算力、通信这条系统侧暗线怎么在背后筛掉了一部分方案。

**为什么写这篇**：讲架构的文章大多是一份清单——RoPE、GQA、MoE、Mamba 各讲一段，看完记住了名词，但不清楚它们为什么按这个顺序出现，也不清楚改动一处会牵动哪里。所以这篇换了个拆法：把 Transformer 分成位置编码、归一化、残差连接、FFN/MoE、注意力五块，每块单独顺着时间捋一遍，再回头看它们之间怎么互相牵制。一句话结论——

> **到 2026 年，位置编码、归一化、FFN 这三块的做法基本已经稳定；残差连接（2024 年起开始有人改动）和注意力（至今仍在变）是仅剩的两个活跃方向。单个 Block 内部可改的空间已经不多，现在的重点是层与层之间怎么组织。**

**怎么读**：时间有限就只看 §2，那是十三条个人判断，全文结论都在里面 → 再看 §3 的三张全景图建立坐标 → §4 说明五块分别位于 Block 的哪个位置 → §5-§9 是五条路线的正文，按兴趣挑 → §10-§12B 是几个专题 → §13-§14 收尾，附一张现状总表和迁移到其他领域时的三条提醒。

**几条主要观点**：

- **单 Block 内部的空间已经不多**：一个 Block 里能试的组合基本被穷举完了，能改的只剩层与层之间怎么连、怎么配比。2026 年那四篇代表性论文没有一篇发明新算子，全都在调整层间的组织方式。
- **五条路线应对的是同一个压力**：背后都是三个数在变大——n（上下文）、L（层数）、N（参数）。整部架构史可以看成一部不断为规模增长补上边界的历史。哪个数先到极限，对应那条路线就先变得活跃。
- **能不能稳定下来，取决于要同时满足几个目标**：只需顾一件事的（位置编码、归一化、MoE）都比较早定型；注意力要同时顾五件事（显存、算力、精度、长距离检索、训练稳定性），彼此冲突，所以一直没有定论。
- **稀疏还有第四个轴没被系统开发**：MoE 在专家维度稀疏，稀疏注意力在 token 维度稀疏，MLA/低秩在特征/秩维度稀疏——这三个轴都已经做到让模型自己学着选，只有深度（层）这个轴仍然是固定的，每个 token 都要走完全部层。
- **理论上省不等于实际省**：实际收益 = 理论收益 × 工程上能兑现的比例。Flash Attention 把 O(n²) 的开销压到可接受，反而让稀疏和线性方案不再紧迫；而 KV 量化和 MLA 叠加起来是乘法关系（合计省下约 98%）。

**章节结构**：§1 论文索引 ｜ §2 作者洞察（十三条，分五组）｜ §3 五条路线代际地图 ｜ §4 Block 内部坐标系 ｜ §5 位置编码 ｜ §6 归一化 ｜ §7 残差连接 ｜ §8 FFN/MoE ｜ §9 注意力（稠密/稀疏/线性）｜ §10 线性注意力三家公式级对比 ｜ §11 混合架构怎么混 ｜ §12 路线间横向耦合 ｜ §12B 系统侧暗线 ｜ §13 总结判断 ｜ §14 跨领域迁移三条通则

## 📖 rec_model_scaling_infra.md —— 推荐大模型 Scaling&Infra（2025 → 2026）

> 把 2025-2026 年工业界的 25 篇工作（Meta、字节、快手、阿里、腾讯微信、港科大广州）读完之后做的整理，既讲具体技术怎么演进，也讲这些做法背后共同的思路。

**为什么写这篇**：过去十年推荐模型的做法是为 CPU 时代量身设计各种特征交叉模块——DCN 做显式交叉、DIN 做目标注意力、SIM 做长序列检索。这些模块单独看都有道理，但组合起来有一个共同的问题：做不大。参数和数据一旦增长，收益就跟不上了。而 LLM 那边已经反复验证了"架构统一 + 算力投入 = 效果持续提升"。推荐能否照同样的路走？2025-2026 年工业界给的答案是可以，但前提是先解决推荐场景独有的几个工程问题。

**全文怎么组织**：先给 25 篇工作分类、理清脉络，再逐层讲每层怎么演进，然后提炼论文之间共通的规律，最后推演下一步可能的方向。

- **第一节 全景架构** —— 图一六层体系、图二交互 Block 分叉（RankMixer 与 ULTRA-HSTU 的算子之争、阿里的改造路线、HyFormer 的信息流拓扑之问，外加表征健康这条正交维度）、图三八链进化树
- **第二节 七条演进主线** —— Token 化 → 统一交互 Block → 长序列多阶段压缩 → 在线推理与算力解耦 → 底层基建 → 生成式演进，外加和前六条不在一个维度上的第七条：**表征健康**
- **第三节 七个统一主题** —— Memory-Bound→Compute-Bound（所有优化的根源）、Scaling Law 的三层前提、近线计算的"时间套利"、Co-Design、四家技术路径对比、特征工程→Token 工程、MFU 之外的第二条体检线
- **第四节 可推断的突破方向** —— 4.1-4.9 是当前范式内的方向（带 P0/P1/P2 优先级表），4.10 是三个代际性拐点
- **附录** —— 术语对照表（架构与算子 / 表征健康 / 推理与部署 / 训练与系统 / 范式与业务指标）

**几条主要观点**：

- **所有优化的根源是 GPU 没被喂饱**：大量碎片化的小算子让 GPU 多数时间在等数据（MFU 只有个位数），只有把它们合并成大 GEMM，Scaling Law 才有讨论的基础。RankMixer 把 MFU 从 4.5% 提到 45%，是这件事最直观的例子。
- **Scaling Law 有三个前提，业界普遍只验证了两个**：架构要能做大、数据要够（反馈回路、语义特征），还有第三个——参数增加之后，表征是否真的展开了（effective rank 会不会反而下降）。这三条是相互独立的失效原因，不是必须依次满足的阶梯。
- **近线计算是推荐独有的优势**：这是 LLM 想要也没有的条件——长序列压缩可以放到离线/近线提前算好，线上只保留少量轻量交互。
- **论文里的增益数字不能横向并列**：各篇的 GMV、转化率、LT30 量级差好几个数量级，A/B 的置信区间和流量规模又大多没披露。这些数字能证明"Scaling 在特定场景生效"，不能证明"Scaling 必然有效"——没有收益的尝试通常不会写成论文。
- **"把 GPU 用满"只是阶段性任务**：当前这一波围绕 MFU、GEMM、Roofline 的工作，本质是推荐系统在补"硬件是否用对"这一课，必要，但会过去。真正的换代来自范式变化——打分变成生成、被动拟合数据分布变成主动塑造分布（RecRLHF，以及随之而来的价值对齐问题）、每个场景训一个模型变成一个基座加若干轻量适配。
- **今天最划算的推理优化，可能在下一代失效得最快**：现在为了给 B 个候选快速打分所做的工程攻坚，到了生成式那边并不存在这个问题；下一代推荐的推理引擎，更可能是从 vLLM 这类 LLM 推理栈迁移过来，而不是从现有推荐引擎演化而来。

## 📖 scaling_infra_papers_breakdown.md —— 25 篇论文逐篇精读

> 上一篇的证据底稿。25 篇论文每篇按「做了什么 / 为什么这么做 / 原始论文深度见解 / 工业验证数据」四段拆开，后面接八个横向维度。想快速了解趋势读上一篇，想核实某篇论文到底怎么说的读这篇。

**为什么单独成篇**：综述类文章有个通病——为了叙事流畅，会把论文的机制简化成一句话，简化过程中经常失真。这篇的做法相反，宁可写得啰嗦，也要把机制写准。**很多论文的实际做法和它摘要给人的第一印象并不一致**，这类地方都在正文里点明了，例如：

- ULTRA-HSTU 的 SLA 不是"近处精确、远处摘要"的分层压缩，K2 是全局 prefix 里真实存在的 token，不做压缩也不做低秩近似——区别在感受野，不在精度。
- MixFormer 的 user-item 解耦靠的是 masking（屏蔽 user head → item head 的信息流），不是架构上的切分。
- LLaTTE 拟合的是对数线性形式（ΔNE ∝ −α·log₁₀C），不是幂律——这一点和 LLM 的幂律形式不同，容易被顺手写成幂律。
- HyFormer 是在"LONGER 压缩 + RankMixer 融合"这条解耦流水线之后提出的改进方案，时间上晚于两者，不是上游源头。

**结构**：主线一 Token 化（4 篇）｜ 主线二 统一交互 Block（9 篇）｜ 主线三 长序列（3 篇）｜ 主线四 推理解耦（2 篇）｜ 主线五 底层基建（3 篇）｜ 主线六 生成式推荐（2 篇）｜ 主线七 表征健康（2 篇）——共 25 篇。之后是八个横向维度：跨论文对比、瓶颈依赖链、工程实践映射、前瞻性分析、GEMM/Roofline 量化、三层前提框架、主线交叉引用、14 个深度新见解。最后附一张 25 篇的工业验证数据汇总表。

**引用时请注意**：逐篇部分的机制描述和线上数据来自论文原文；八个横向维度里的对比、归类和推断属于本文档的归纳，已在对应段落标注。少数论文存在 arXiv 版本间数据差异，或摘要与正文口径不一致，这类情况也都标了出来。
